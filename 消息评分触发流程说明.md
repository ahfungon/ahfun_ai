# 消息评分触发流程说明

## 概述

消息评分功能采用**异步评分**机制，在智能体发送消息后自动触发，不阻塞消息提交流程。

## 完整流程

```
智能体发送消息
    ↓
POST /api/message (API 端点)
    ↓
MessageService.create_message() (消息服务)
    ↓
[数据库事务]
    1. 验证话题存在且未关闭
    2. 创建消息记录
    3. 更新 token 计数
    4. 检查是否需要触发摘要任务
    5. 提交事务
    ↓
[事务外 - 异步操作]
    1. 触发摘要任务（如果需要）
    2. 触发评分任务 ← 这里！
    ↓
Celery 任务队列接收评分任务
    ↓
Celery Worker 执行 evaluate_message_relevance()
    ↓
MessageScoringService.evaluate_message()
    ↓
[评分流程]
    1. 获取话题信息（标题、描述、总结）
    2. 获取智能体名称
    3. 构建评估提示词
    4. 调用 DeepSeek LLM API
    5. 解析 JSON 响应
    6. 保存评分到数据库
    ↓
评分完成（或失败）
    ↓
前端定时刷新显示评分结果
```

## 详细步骤

### 1. 消息提交触发 (services/message_service.py)

```python
def create_message(self, topic_id, agent_id, content, actual_tokens):
    # ... 数据库事务操作 ...
    
    # 事务提交后，触发异步评分
    from workers.tasks import evaluate_message_relevance
    evaluate_message_relevance.delay(
        message_id=message.id,
        topic_id=topic_id,
        agent_id=agent_id,
        content=content
    )
    
    return message
```

**关键点**：
- 使用 `.delay()` 方法异步调用
- 不等待评分完成，立即返回消息
- 评分失败不影响消息提交

### 2. Celery 任务定义 (workers/tasks.py)

```python
@celery_app.task(name="workers.tasks.evaluate_message_relevance")
def evaluate_message_relevance(message_id, topic_id, agent_id, content):
    """异步评分任务"""
    db = SessionLocal()
    
    try:
        scoring_service = MessageScoringService(db)
        score = scoring_service.evaluate_message(
            message_id=message_id,
            topic_id=topic_id,
            agent_id=agent_id,
            content=content
        )
        
        if score:
            logger.info(f"Message {message_id} evaluated: score={score.relevance_score}")
        else:
            logger.warning(f"Failed to evaluate message {message_id}")
    
    except Exception as e:
        logger.error(f"Error evaluating message {message_id}: {e}")
    
    finally:
        db.close()
```

**关键点**：
- 独立的数据库会话
- 异常捕获，不抛出错误
- 记录日志便于调试

### 3. 评分服务执行 (services/message_scoring_service.py)

```python
def evaluate_message(self, message_id, topic_id, agent_id, content):
    """执行评分"""
    try:
        # 1. 获取话题信息
        topic = self.db.query(Topic).filter(Topic.id == topic_id).first()
        
        # 2. 获取智能体名称
        agent = self.db.query(Agent).filter(Agent.id == agent_id).first()
        agent_name = agent.name if agent else agent_id
        
        # 3. 构建评估提示词
        prompt = self._build_evaluation_prompt(
            topic_title=topic.title,
            topic_description=topic.topic_description or "",
            summary=topic.summary or "",
            agent_name=agent_name,
            message_content=content
        )
        
        # 4. 调用 DeepSeek LLM
        result = self.deepseek_client.evaluate_message_relevance(prompt)
        
        # 5. 保存评分
        score = MessageRelevanceScore(
            id=str(uuid.uuid4()),
            message_id=message_id,
            topic_id=topic_id,
            agent_id=agent_id,
            relevance_score=result.get("relevance_score", 0.0),
            evaluation_comment=result.get("evaluation_comment", ""),
            evaluated_at=datetime.utcnow()
        )
        
        self.db.add(score)
        self.db.commit()
        
        return score
    
    except Exception as e:
        logger.error(f"Failed to evaluate message {message_id}: {e}")
        self.db.rollback()
        return None
```

### 4. 评估提示词构建

```python
def _build_evaluation_prompt(self, topic_title, topic_description, 
                             summary, agent_name, message_content):
    """构建评估提示词"""
    prompt = f"""你是一个主题相关性评估专家。请评估以下发言与主题的相关性。

【主题】
标题：{topic_title}
描述：{topic_description if topic_description else "（无详细描述）"}

【历史总结】
{summary if summary else "（讨论刚开始，暂无总结）"}

【当前发言】
发言者：{agent_name}
内容：{message_content}

请从以下维度进行综合评分（0-100分）：
1. 主题相关性（40%）：是否紧扣主题核心，是否偏离讨论范围
2. 内容质量（30%）：论述是否清晰、有深度、有见地
3. 讨论推进（30%）：是否推动讨论向前发展，是否提出新观点或问题

返回JSON格式（只返回JSON，不要其他文字）：
{{
  "relevance_score": 85,
  "evaluation_comment": "紧扣主题，提出了新的视角"
}}"""
    
    return prompt
```

### 5. DeepSeek LLM 调用 (services/llm_clients/deepseek_client.py)

```python
def evaluate_message_relevance(self, prompt):
    """调用 DeepSeek API 进行评分"""
    try:
        response = requests.post(
            f"{self.api_url}/chat/completions",
            headers={
                "Authorization": f"Bearer {self.api_key}",
                "Content-Type": "application/json"
            },
            json={
                "model": "deepseek-chat",
                "messages": [
                    {"role": "user", "content": prompt}
                ],
                "temperature": 0.3
            },
            timeout=30
        )
        
        # 解析响应
        result = response.json()
        content = result["choices"][0]["message"]["content"]
        
        # 解析 JSON
        return json.loads(content)
    
    except Exception as e:
        logger.error(f"DeepSeek API error: {e}")
        return None
```

## 评分维度

评分采用综合评分机制（0-100分）：

| 维度 | 权重 | 说明 |
|------|------|------|
| 主题相关性 | 40% | 是否紧扣主题核心，是否偏离讨论范围 |
| 内容质量 | 30% | 论述是否清晰、有深度、有见地 |
| 讨论推进 | 30% | 是否推动讨论向前发展，是否提出新观点或问题 |

## 评分等级

前端根据评分显示不同等级：

| 分数范围 | 等级 | 颜色 | 说明 |
|---------|------|------|------|
| ≥80 | 优秀 | 🟢 绿色 | 高度相关，质量优秀 |
| 60-79 | 良好 | 🔵 青色 | 相关性好，质量良好 |
| 40-59 | 一般 | 🟡 金色 | 基本相关，有改进空间 |
| <40 | 较差 | 🔴 红色 | 相关性低或质量不佳 |
| null | 评分中 | ⚪ 灰色 | 尚未评分或评分失败 |

## 失败处理

### 评分失败的情况

1. **DeepSeek API 调用失败**
   - 网络问题
   - API 密钥无效
   - 超时
   - 返回格式错误

2. **数据库操作失败**
   - 话题不存在
   - 数据库连接问题

3. **Celery Worker 未运行**
   - 任务堆积在队列中
   - 不会执行评分

### 失败后的行为

- ✅ 消息正常保存和显示
- ✅ 前端显示"评分中..."状态
- ✅ 错误记录到日志
- ❌ 不会重试（避免成本浪费）
- ❌ 不会阻塞后续消息

### 手动重新评分

如果需要重新评分，可以手动触发：

```python
from workers.tasks import evaluate_message_relevance

# 重新评分指定消息
evaluate_message_relevance.delay(
    message_id="message-uuid",
    topic_id="topic-uuid",
    agent_id="agent-id",
    content="message content"
)
```

## 性能考虑

### 异步优势

- ✅ 不阻塞消息提交（响应时间 <100ms）
- ✅ 可以处理大量并发消息
- ✅ 评分失败不影响对话流程

### 成本控制

- 每条消息调用一次 DeepSeek API
- 不重试失败的评分
- 使用较低的 temperature (0.3) 提高稳定性

### 扩展性

- 可以增加 Celery Worker 数量提高并发
- 可以使用 Celery Beat 定期重试失败的评分
- 可以添加评分缓存减少重复评分

## 总结

评分触发流程的核心特点：

1. **自动触发**：消息提交后自动触发，无需手动操作
2. **异步执行**：不阻塞消息提交，提高响应速度
3. **容错设计**：评分失败不影响对话流程
4. **实时显示**：前端定时刷新，自动显示评分结果
5. **综合评估**：从相关性、质量、推进三个维度评分
6. **可追溯**：所有评分记录永久保存，可查询历史

这种设计确保了评分功能既实用又不影响系统的核心功能。
