修复时间: 2026-02-25

## 问题描述

在明宽服务器的评分监控页面（admin.html），访问时出现以下错误：

### 前端错误
```
加载失败: Cannot read properties of undefined (reading 'api_key_configured')
```

### 后端错误（500 Internal Server Error）
```

```

### 服务器日志错误
```python
File "/home/ubuntu/dual-agent-chat/api/routes.py", line 2211, in get_scoring_stats
    delay = round((m.evaluated_at - m.created_at).total_seconds(), 1)
                   ~~~~~~~~~~~~~~~^~~~~~~~~~~~~~
TypeError: can't subtract offset-naive and offset-aware datetimes
```

## 根本原因

### 时区不一致问题

数据库中两个时间字段的类型不一致：

1. **message_relevance_scores.evaluated_at**
   - 类型: `timestamp with time zone` (timezone-aware)
   - 包含时区信息

2. **messages.created_at**
   - 类型: `timestamp without time zone` (timezone-naive)
   - 不包含时区信息

当尝试计算两个时间的差值时：
```python
delay = round((m.evaluated_at - m.created_at).total_seconds(), 1)
```

Python 无法直接相减 timezone-aware 和 timezone-naive 的 datetime 对象，导致 `TypeError`。

### 为什么会出现这个问题？

这是数据库迁移时的设计不一致：
- `message_relevance_scores` 表是后来添加的，使用了 `DateTime(timezone=True)`
- `messages` 表是早期创建的，使用了 `DateTime(timezone=False)`

## 解决方案

### 修复代码

在计算时间差之前，统一处理时区：

```python
# 旧代码（有问题）
if scored and m.evaluated_at and m.created_at:
    delay = round((m.evaluated_at - m.created_at).total_seconds(), 1)
```

```python
# 新代码（修复后）
if scored and m.evaluated_at and m.created_at:
    # Handle timezone-aware and timezone-naive datetime comparison
    try:
        # If evaluated_at is timezone-aware, convert created_at to UTC
        if m.evaluated_at.tzinfo is not None:
            from datetime import timezone
            created_at_utc = m.created_at.replace(tzinfo=timezone.utc) if m.created_at.tzinfo is None else m.created_at
            delay = round((m.evaluated_at - created_at_utc).total_seconds(), 1)
        else:
            delay = round((m.evaluated_at - m.created_at).total_seconds(), 1)
    except (TypeError, AttributeError):
        delay = None
```

### 修复逻辑

1. **检查时区信息**: 判断 `evaluated_at` 是否包含时区信息
2. **统一时区**: 如果 `evaluated_at` 有时区而 `created_at` 没有，给 `created_at` 添加 UTC 时区
3. **异常处理**: 捕获可能的类型错误，避免程序崩溃
4. **降级处理**: 如果计算失败，返回 `None` 而不是抛出异常

## 技术细节

### Python datetime 时区处理

#### timezone-aware datetime
```python
from datetime import datetime, timezone
dt = datetime.now(timezone.utc)  # 带时区
print(dt.tzinfo)  # <UTC>
```

#### timezone-naive datetime
```python
from datetime import datetime
dt = datetime.now()  # 不带时区
print(dt.tzinfo)  # None
```

#### 转换方法
```python
# 给 naive datetime 添加时区
naive_dt = datetime.now()
aware_dt = naive_dt.replace(tzinfo=timezone.utc)

# 或者使用 astimezone
aware_dt = naive_dt.astimezone(timezone.utc)
```

### PostgreSQL 时间类型

| Python SQLAlchemy | PostgreSQL | 说明 |
|-------------------|------------|------|
| `DateTime(timezone=False)` | `timestamp without time zone` | 不存储时区信息 |
| `DateTime(timezone=True)` | `timestamp with time zone` | 存储时区信息 |

### 最佳实践

1. **统一使用 timezone-aware datetime**
   ```python
   # 推荐
   created_at = Column(DateTime(timezone=True), default=lambda: datetime.now(timezone.utc))
   ```

2. **数据库迁移时保持一致性**
   - 所有时间字段使用相同的时区设置
   - 优先使用 `timestamp with time zone`

3. **代码中处理时区**
   ```python
   # 总是检查时区
   if dt.tzinfo is None:
       dt = dt.replace(tzinfo=timezone.utc)
   ```

### 3. 添加时区工具函数

创建统一的时区处理工具：

```python
# utils/datetime_utils.py
from datetime import datetime, timezone

def ensure_timezone_aware(dt: datetime) -> datetime:
    """确保 datetime 对象包含时区信息"""
    if dt is None:
        return None
    if dt.tzinfo is None:
        return dt.replace(tzinfo=timezone.utc)
    return dt

def safe_timedelta(dt1: datetime, dt2: datetime) -> float:
    """安全计算两个时间的差值（秒）"""
    try:
        dt1 = ensure_timezone_aware(dt1)
        dt2 = ensure_timezone_aware(dt2)
        return (dt1 - dt2).total_seconds()
    except (TypeError, AttributeError):
        return None
```
