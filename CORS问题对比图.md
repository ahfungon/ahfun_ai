# CORS 问题对比图

## 问题场景：直接调用（失败）

```
┌─────────────────────────────────────────────────────────────┐
│                        浏览器                                │
│  (localhost:8080)                                           │
│                                                             │
│  ┌──────────────────────────────────────┐                  │
│  │  前端智能体模拟器                      │                  │
│  │  (admin.html)                        │                  │
│  │                                      │                  │
│  │  fetch('https://api.minimax.chat')  │                  │
│  └──────────────┬───────────────────────┘                  │
│                 │                                           │
│                 │ ❌ CORS 错误                              │
│                 │ (浏览器阻止跨域请求)                       │
└─────────────────┼───────────────────────────────────────────┘
                  │
                  ▼
         ┌────────────────┐
         │  MiniMax API   │
         │ (api.minimax.  │
         │    chat)       │
         │                │
         │ ❌ 没有 CORS   │
         │    响应头      │
         └────────────────┘
```

**问题原因：**
- 浏览器从 `localhost:8080` 访问 `api.minimax.chat` 是跨域请求
- MiniMax API 服务器没有返回 `Access-Control-Allow-Origin` 头
- 浏览器的安全策略阻止了这个请求
- 错误信息：`Failed to fetch`

---

## 解决方案：后端代理（成功）

```
┌─────────────────────────────────────────────────────────────┐
│                        浏览器                                │
│  (localhost:8080)                                           │
│                                                             │
│  ┌──────────────────────────────────────┐                  │
│  │  前端智能体模拟器                      │                  │
│  │  (admin.html)                        │                  │
│  │                                      │                  │
│  │  fetch('/api/admin/llm/proxy')      │                  │
│  └──────────────┬───────────────────────┘                  │
│                 │                                           │
│                 │ ✅ 同源请求                               │
│                 │ (localhost → localhost)                  │
└─────────────────┼───────────────────────────────────────────┘
                  │
                  ▼
         ┌────────────────────────────────────┐
         │      后端服务器                     │
         │   (localhost:8080)                 │
         │                                    │
         │  ┌──────────────────────────────┐  │
         │  │  代理端点                     │  │
         │  │  /api/admin/llm/proxy        │  │
         │  │                              │  │
         │  │  1. 接收前端请求              │  │
         │  │  2. 读取系统配置 API Key      │  │
         │  │  3. 调用 LLM API             │  │
         │  │  4. 返回响应给前端            │  │
         │  └──────────────┬───────────────┘  │
         │                 │                   │
         │                 │ ✅ 服务器请求     │
         │                 │ (不受 CORS 限制)  │
         └─────────────────┼───────────────────┘
                           │
                           ▼
                  ┌────────────────┐
                  │  MiniMax API   │
                  │ (api.minimax.  │
                  │    chat)       │
                  │                │
                  │ ✅ 正常响应    │
                  └────────────────┘
```

**解决原理：**
- 前端访问 `/api/admin/llm/proxy` 是同源请求（localhost → localhost）
- 后端服务器调用 MiniMax API 是服务器到服务器的请求
- 服务器请求不受浏览器 CORS 策略限制
- 后端代理转发响应给前端

## 为什么 DeepSeek 可以但 MiniMax 不行？

### DeepSeek API（支持 CORS）

```
浏览器 (localhost:8080)
    │
    │ fetch('https://api.deepseek.com/v1/chat/completions')
    │
    ▼
DeepSeek API
    │
    │ 响应头包含：
    │ Access-Control-Allow-Origin: *
    │ Access-Control-Allow-Methods: POST, GET, OPTIONS
    │ Access-Control-Allow-Headers: Content-Type, Authorization
    │
    ▼
✅ 浏览器允许跨域请求
```

### MiniMax API（不支持 CORS）

```
浏览器 (localhost:8080)
    │
    │ fetch('https://api.minimax.chat/v1/chat/completions')
    │
    ▼
MiniMax API
    │
    │ 响应头不包含：
    │ ❌ 没有 Access-Control-Allow-Origin
    │
    ▼
❌ 浏览器阻止跨域请求
   错误：Failed to fetch
```

## 性能对比

### 直接调用

```
前端 ──────────────────────────────▶ MiniMax API
     │                                    │
     │◀───────────────────────────────────┤
     
总延迟 = LLM API 响应时间 (1-3秒)
```

### 代理调用

```
前端 ──────▶ 后端代理 ──────────────▶ MiniMax API
     │           │                        │
     │           │◀───────────────────────┤
     │◀──────────┤
     
总延迟 = 代理延迟 (<10ms) + LLM API 响应时间 (1-3秒)
       ≈ LLM API 响应时间 (代理延迟可忽略)
```

**结论：** 代理增加的延迟 < 1%，对用户体验无影响

## 总结

| 方面 | 直接调用 | 代理调用 |
|------|---------|---------|
| CORS 问题 | ❌ 被阻止 | ✅ 解决 |
| API Key 安全 | ❌ 暴露在前端 | ✅ 存储在后端 |
| 配置管理 | ❌ 分散在前端 | ✅ 统一在系统配置 |
| 错误处理 | ❌ 前端处理 | ✅ 后端统一处理 |
| 性能影响 | 0ms | < 10ms (可忽略) |
| 可扩展性 | ❌ 难以扩展 | ✅ 易于扩展 |
| 推荐使用 | ❌ 不推荐 | ✅ 推荐 |

**最佳实践：** 使用后端代理调用 LLM API
